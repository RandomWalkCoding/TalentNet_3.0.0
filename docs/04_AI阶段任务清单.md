# 04 AI 阶段任务清单

## 1. 执行规则

本清单用于从当前 Demo 继续推进到“真实数据链路 + LLM 接入 + Demo PRD P1 补齐”的 MVP。

硬性规则：

1. 每个阶段作为独立会话执行。
2. 每个阶段先后端、再前端，后端必须串行于前端。
3. 每个阶段创建分支：`feature/stage-<阶段编号>`。
4. 新阶段基于上一阶段分支创建。
5. 每个阶段结束时项目必须可运行。
6. 前端只展示和提交操作，AI、浏览器任务、评分、数据库全部在后端。
7. 依赖不提交，`node_modules`、`.next`、SQLite 运行库、缓存都不能进仓库。

## 2. Demo PRD P1 覆盖说明

Demo PRD P1 包含三块：

| P1 功能 | 并入阶段 |
|---|---|
| AI 浏览器任务面板真实链路 | 阶段 5 |
| 半自动组织关系图 | 阶段 9 |
| 管理者视图 | 阶段 10 |

阶段 0-8 用于把 P0 主链路跑实。阶段 9-10 专门补齐 Demo PRD 的 P1 能力。

### 后端

- 确认 pytest 使用临时数据库，不污染项目目录。
- 检查 `BrowserTaskService`、`LLMService`、`RiskScoringService` 的真实缺口。

### 前端

- 清理中文文案乱码。
- 确认页面能调用当前 API。
- 确认前端依赖不提交。

### 文档

- 更新模块划分、数据选型、代码规范。
- 输出 PRD 功能差距审阅。

### 验收

- `python -m pytest` 通过。
- 乱码扫描无命中。
- `git status` 不出现依赖和构建产物。

## 4. 阶段 1：真实证据录入链路

## 5. 阶段 2：LLM Gateway 与真实模型调用

- 支持 OpenAI-compatible 配置：

- 增加 Prompt 模板。
- 增加 JSON schema 校验。
- 增加 evidence_id 引用校验。
- LLM 不可用时降级为本地模板。
- 增加 mock 测试。

### 前端

- AI 面板显示模型状态、生成中、失败、降级提示。
- 展示 cited evidence。
- 保留可编辑触达话术。

### 验收

- 配置 API Key 后能调用真实 LLM。
- 无 API Key 时仍可用本地降级。
- LLM 输出必须引用当前候选人的证据。

## 8. 阶段 5：AI 浏览器任务真实执行（P1）

这是 Demo PRD P1 的“AI 浏览器任务面板”完整实现阶段。

### 后端

- 接入 Playwright 执行层。
- 支持打开目标 URL 或搜索 URL。
- 读取页面 title、url、visible text。
- 保存截图到 `artifacts/browser-tasks`。
- 调用 LLM 抽取 evidence draft。
- 记录 execution_log。
- 支持任务失败、取消、重试。
- 不保存密码，不绕过验证码，不绕过平台权限。
- LinkedIn/脉脉只支持用户授权后的可见页面辅助读取，不做批量采集。

### 前端

- 任务页展示执行日志。
- 展示截图路径或预览。
- 展示页面标题、URL、读取时间。
- 草稿确认前可编辑。
- 支持失败重试。
- 明确展示合规提示。

### 验收

- 至少能对公开网页跑通：打开、读取、抽取、确认、入库、评分刷新。
- 任务状态可追踪。
- 证据必须人工确认后才入库。

## 12. 阶段 9：半自动组织关系图（P1）

这是 Demo PRD P1 的“半自动组织关系图”实现阶段。

### 后端

- 新增组织关系数据模型：
  - `Relationship`
  - `RelationshipEvidence`
- 关系类型至少支持：
  - same_company
  - same_department
  - same_project
  - co_author
  - manager_report
  - peer_movement
  - suspected_relation
- 新增关系生成服务 `RelationshipGraphService`。
- 基于候选人公司、部门、项目关键词、论文/专利合作者、证据摘要生成候选关系。
- LLM 只能用于“关系候选解释”，不得无证据创建确定关系。
- 所有关系必须有 confidence 和 evidence_ids。
- 新增 API：
  - `GET /api/companies/{id}/relationship-graph`
  - `POST /api/relationship-graph/rebuild`
  - `PATCH /api/relationships/{id}`
- 增加测试。

### 前端

- 新增组织关系图页面或公司详情里的关系图区域。
- 展示节点：
  - 已确认候选人
  - 疑似关系节点
  - 已离任/已关闭节点
- 展示边：
  - 关系类型
  - 置信度
  - 证据数量
- 支持点击节点进入候选人详情。
- 支持点击边查看证据来源。
- 支持用户确认/否定关系。

### 验收

- 至少能从 seed 或真实录入数据生成一个公司关系图。
- 每条边都有 evidence_ids 或明确标记为 suspected_relation。
- 用户能确认/否定关系。
- 前端不做关系推断，只展示后端返回的 graph JSON。

## 13. 阶段 10：管理者视图（P1）

这是 Demo PRD P1 的“管理者视图”实现阶段。

### 后端

- 增加团队/成员/角色基础模型：
  - `User`
  - `Team`
  - `TeamMember`
- 增加管理者聚合服务 `ManagerAnalyticsService`。
- 指标至少包含：
  - 团队候选人查看数
  - 猎场加入数
  - 触达数
  - 反馈记录率
  - bad_prediction 数
  - LLM 使用次数
  - 席位使用情况
- 新增 API：
  - `GET /api/manager/summary`
  - `GET /api/manager/team-activity`
  - `GET /api/manager/seats`
- 增加 RBAC 校验，只有管理员可访问。
- 增加测试。

### 前端

- 新增 `/manager` 页面。
- 展示团队指标卡、成员活跃列表、反馈漏斗、席位状态。
- 普通用户不显示管理者入口。
- 无权限访问时展示 403 友好错误。

### 验收

- 管理员能查看团队反馈率、猎场转化和席位使用。
- 普通用户不能访问管理者视图。
- 指标来自真实 feedback、talent_pool、llm_runs、audit_logs，而不是前端 mock。

## 14. 前后端分离检查清单

每阶段结束都检查：

- 前端没有数据库访问。
- 前端没有 LLM API Key。
- 前端没有 Playwright 控制逻辑。
- 后端 API schema 清晰。
- 后端测试覆盖核心写操作。
- AI 输出有证据引用。
- 证据入库前需要用户确认。
- 依赖和构建产物不进入仓库。
