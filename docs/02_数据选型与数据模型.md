# 02 数据选型与数据模型

## 1. 数据选型结论

当前代码使用 SQLite，适合本地 Demo。下一阶段为了跑真实数据链路，仍可短期保留 SQLite，但必须补齐数据边界、迁移方案和测试隔离。

推荐路径：

| 阶段 | 数据库 | 文件存储 | 任务队列 | 适用场景 |
|---|---|---|---|---|
| V0.2 真实链路 Demo | SQLite | 本地 artifacts | 同步/轻量后台任务 | 单机演示、快速验证 |
| V0.5 内测 MVP | PostgreSQL | 本地或 MinIO | Redis + Celery/Dramatiq | 小团队多人使用 |
| V1.0 生产 | PostgreSQL + pgvector | S3/OSS/MinIO | Worker 集群 | 多租户、审计、扩展 |

## 5. 数据流

### 5.1 证据入库

```text
BrowserTask / 手动录入 / CSV 导入
  -> EvidenceDraft
  -> LLM 抽取摘要和字段
  -> 用户确认
  -> Evidence
  -> refresh score
```

### 5.2 LLM 输出

```text
Candidate + Evidence[]
  -> PromptInput
  -> LLM
  -> JSON schema validation
  -> evidence_id validation
  -> LLMRun audit
  -> 返回前端或写入评分解释
```

### 5.3 测试数据隔离

测试环境必须通过 `TALENTNET_DATABASE_URL` 使用临时目录数据库，不得在 `backend/` 下生成 `talentnet.db`。

当前已新增 `backend/tests/conftest.py`，pytest 会把测试库放到系统临时目录。

## 6. 迁移策略

- V0.2 保留 SQLAlchemy 模型，先不引入复杂迁移。
- V0.5 引入 Alembic，所有 schema 变更必须通过 migration。
- Repository/Service 不直接依赖 SQLite 特性，为 PostgreSQL 迁移保留空间。
- JSON 字段在 SQLite 中可用，生产 PostgreSQL 使用 JSONB。
