# 01 技术架构与模块划分

## 1. 架构目标

TalentNet 下一阶段目标是从“种子数据 Demo”升级为“可跑真实数据链路的 MVP”：

- 用户可以导入或手动创建公司、候选人和证据。
- 后端可以通过受控网页任务生成证据草稿。
- 后端接入 LLM，对证据做结构化摘要、风险解释、冲突识别和触达话术生成。
- 所有 AI 结论必须可追溯到 evidence，且需要人工确认后进入评分链路。
- 前后端严格分离：前端只展示和提交操作，后端负责数据、任务、AI、评分和持久化。

## 2. 前后端分离边界

### 2.1 前端职责

- 页面路由、布局、筛选、表格、卡片、表单和交互状态。
- 调用后端 REST API。
- 展示候选人、公司、证据、评分、LLM 解释和触达话术。
- 提交用户确认、反馈、筛选条件和任务创建请求。
- 只保存短生命周期 UI 状态，不保存业务事实。

### 2.2 后端职责

- 管理业务实体：公司、候选人、证据、评分、猎场、反馈、坏例、任务。
- 控制网页任务、证据抽取、截图路径、状态流转。
- 调用 LLM，并做 JSON schema 校验、引用证据校验、错误兜底。
- 运行风险评分规则，写入评分记录。
- 管理数据库、文件存储、审计日志和配置。
- 保护 API Key、Cookie、浏览器会话和模型配置。

### 2.3 禁止事项

- 前端不得直接访问数据库。
- 前端不得直接调用 LLM API。
- 前端不得直接执行 Playwright。
- 前端不得保存 API Key、Cookie、账号密码。
- AI 不得自动向候选人发送消息。
- 网页任务不得绕过验证码、登录权限或平台限制。

## 3. 推荐技术栈

| 层级 | 当前/下一阶段 | 生产演进 |
|---|---|---|
| 前端 | Next.js + React + TypeScript + Tailwind CSS | 保持，沉淀设计系统 |
| 后端 | FastAPI + SQLAlchemy + Pydantic | 保持 |
| 数据库 | SQLite | PostgreSQL |
| 迁移 | 暂无 | Alembic |
| 异步任务 | 同步 Demo service | Redis + Celery/Dramatiq |
| LLM | 后端 LLMGateway | 多模型路由、缓存、审计 |
| 浏览器任务 | 后端 BrowserTaskService | 独立 Browser Worker |
| 文件存储 | 本地 artifacts | S3/OSS/MinIO |
| 观测 | pytest + 日志 | Sentry + Prometheus/Grafana |

## 5. 后端服务模块

| 服务 | 责任 | 当前状态 | 下一步 |
|---|---|---|---|
| CandidateService/Repository | 候选人查询、详情、状态 | 基础可用 | 补导入、搜索、分页 |
| CompanyService/Repository | 公司查询、监测状态 | 基础可用 | 补公司详情、信号聚合 |
| EvidenceService | 证据入库、确认、引用 | 基础可用 | 补人工录入、证据编辑、来源去重 |

| FeedbackService | 触达反馈、坏例 | 基础可用 | 补坏例分类和评分回看 |
| AnalyticsService | 指标聚合 | 基础可用 | 补真实漏斗口径 |

## 6. 真实数据链路

### 6.1 证据链路

```text
用户创建网页任务或人工录入证据
  -> 后端创建 BrowserTask/EvidenceDraft
  -> 网页任务读取用户可见页面或接收人工文本
  -> LLM 抽取结构化证据草稿
  -> 前端展示草稿
  -> 用户确认
  -> 后端写入 Evidence
  -> 触发风险评分刷新
```

### 6.2 LLM 链路

```text
Candidate + Evidence[]
  -> 后端组装 PromptInput
  -> LLMGateway 调用模型
  -> JSON schema 校验
  -> evidence_id 引用校验
  -> 失败时降级为规则解释
  -> 写入或返回 AI 解释/话术
```

### 6.3 评分链路

```text
Evidence 变化
  -> 提取规则特征
  -> 计算 risk_score/confidence_score
  -> LLM 做解释、冲突提示、限制说明
  -> 写入 CandidateScore
  -> 前端刷新评分卡
```

### 6.4 反馈闭环

```text
用户记录 Outcome
  -> Feedback 入库
  -> 更新 Candidate/TalentPool 状态
  -> bad_prediction 写入 Badcase
  -> Analytics 重新聚合
  -> 后续作为评估/校准数据
```

## 8. 当前主要缺口

- LLM 仍是本地模板，不是真实模型调用。
- BrowserTask 仍是模拟证据草稿，不读取真实网页内容。
- 没有人工证据录入 API 和 CSV 导入。
- 没有分页、搜索、排序的标准化接口。
- 没有用户、租户、权限、审计。
- 没有迁移系统，SQLite 适合 Demo，不适合多人 MVP。
- 评分解释中仍有部分旧乱码文案，需要统一清理。
