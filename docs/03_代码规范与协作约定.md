# 03 代码规范与协作约定

## 1. 总原则

- 前后端分离，后端先行定义 schema 和 API，前端再对接。
- 每个阶段必须保持项目可运行。
- AI、Playwright、数据库、API Key 全部在后端。
- 前端只做展示、输入、确认和反馈。
- 代码优先可读、可测、可回滚，不为 Demo 写不可维护的捷径。

## 2. 分支与阶段

- 阶段分支命名：`feature/stage-<编号>`。
- 新阶段基于上一阶段分支创建。
- 一个阶段只做该阶段任务，不跨阶段偷做。
- 每个阶段结束必须更新阶段验收文档。

## 3. 后端规范

### 3.1 目录职责

| 目录 | 责任 |
|---|---|
| `app/api` | FastAPI router，只做参数接收和返回 |
| `app/schemas` | Pydantic schema |
| `app/models` | SQLAlchemy model |
| `app/repositories` | 数据查询与写入 |
| `app/services` | 业务逻辑 |
| `app/core` | 配置、数据库、错误、日志 |
| `tests` | pytest 测试 |

### 3.2 API 规范

- 返回 JSON。
- 错误统一使用：

```json
{
  "error": {
    "code": "ERROR_CODE",
    "message": "Human readable message.",
    "details": {}
  }
}
```

- 路由层不得写复杂业务逻辑。
- Service 抛 `AppError`，由全局 handler 转换。
- 所有写操作必须有测试。

### 3.3 LLM 规范

- 只能在后端调用 LLM。
- LLM 输出必须做 JSON schema 校验。
- 输出中引用的 `evidence_ids` 必须存在且属于当前 candidate。
- 失败时要返回可解释错误或降级为规则解释。
- 不允许把未脱敏 raw_text、API Key、Cookie 返回给前端。
- 每次真实调用要记录 `llm_runs`。

### 3.4 Browser Task 规范

- 不做批量抓取。
- 不绕过验证码、登录权限和平台限制。
- 用户可见页面读取必须在用户授权上下文内执行。
- 证据草稿必须人工确认后才能入库。
- 任务状态必须可追踪：pending/running/waiting_user/completed/failed/cancelled。

### 3.5 测试规范

- 使用 pytest。
- 测试数据库必须走临时目录，不得污染 `backend/talentnet.db`。
- 每个新增 API 至少覆盖：
  - 成功路径
  - 不存在资源
  - 参数错误或权限错误
- LLM 测试默认 mock，不依赖真实网络。

## 4. 前端规范

### 4.1 目录职责

| 目录 | 责任 |
|---|---|
| `app` | Next.js 页面和路由 |
| `components` | 可复用 UI 和交互组件 |
| `lib/api.ts` | API client |
| `lib/labels.ts` | 枚举文案 |
| `lib/utils.ts` | 通用工具 |

### 4.2 UI 规范

- 产品台优先信息密度和可扫描性，不做营销页式大 hero。
- 表格、筛选器、状态标签、按钮、空状态必须完整。
- 所有按钮有 disabled/loading/error 状态。
- 移动端至少不溢出、不遮挡、可横向滚动表格。
- 文案必须中文可读，不得出现乱码。

### 4.3 API 调用规范

- 所有请求通过 `frontend/lib/api.ts`。
- 前端不得拼业务规则。
- 前端不得计算最终风险评分。
- 前端不得保存 LLM 原始配置。

## 5. 数据与隐私规范

- 证据必须记录来源、时间、链接、摘要和置信度。
- 候选人风险是内部排序信号，不是确定离职结论。
- AI 触达话术只供用户编辑复制，不自动发送。
- 任何外部网页结果必须先人工确认。
- Demo 中的 LinkedIn/脉脉能力只作为用户辅助搜索，不承诺生产级采集。

## 6. 依赖和仓库洁净

- 不提交 `node_modules`。
- 不提交 `.next`。
- 不提交 SQLite 运行库。
- 不提交 `__pycache__`、`.pytest_cache`。
- PRD/PDF/docx 资料文件默认不进入代码提交，除非明确作为文档交付。
- 前端依赖需要时执行 `npm install`。
- 后端依赖需要时执行 `python -m pip install -r backend/requirements.txt`。

## 7. 验收命令

后端：

```powershell
cd backend
python -m pytest
```

前端：

```powershell
cd frontend
npm install
npm run build
```

运行：

```powershell
.\start.ps1
```

说明：`start.ps1` 不自动安装前端依赖，避免把依赖无意塞进项目交付包。
