# 00 PRD 功能差距审阅

## 1. 审阅结论

当前项目已经具备一个可演示的 TalentNet MVP 骨架：公司、候选人、证据、评分、猎场、反馈、网页任务、AI 解释和效能分析均有页面和基础 API。

但它仍然是“种子数据 + 模拟任务 + 本地模板 LLM”的 Demo。距离 PRD 里的“真实数据链路、网页证据沉淀、LLM 辅助判断、反馈闭环校准”还有明显差距。

下一阶段目标不是继续堆页面，而是把数据链路跑实：

```text
真实输入
  -> 证据草稿
  -> 人工确认
  -> 风险评分
  -> LLM 解释/话术
  -> 猎场跟进
  -> 反馈闭环
```

## 3. 未完成/未对齐能力

### 3.1 真实数据链路

当前没有真实导入和证据录入闭环。需要补：

- CSV 导入候选人/公司。
- 手动新增候选人、公司、证据。
- 证据草稿编辑。
- 证据去重。
- 证据确认后自动刷新评分。

### 3.2 LLM 接入

当前 `LLMService` 是本地模板，不是真实模型调用。需要补：

- LLMGateway。
- OpenAI-compatible client。
- Prompt 模板版本管理。
- JSON schema 校验。
- LLM 调用审计 `llm_runs`。
- 失败降级策略。

### 3.3 网页任务真实执行

当前 BrowserTask 不打开真实网页，不读取真实内容。需要补：

- Browser Worker 或后端 Playwright 执行层。
- 页面标题、URL、可见文本读取。
- 截图保存。
- 用户确认机制。
- 登录/验证码需要用户处理，不绕过。

### 3.4 评分链路

当前规则评分可用，但解释和特征仍不够完整。需要补：

- 修复后端评分文案乱码。
- 将 evidence source、时间、新鲜度纳入特征。
- LLM 冲突识别影响 confidence_score。
- 保存评分输入快照，便于复盘。

### 3.5 权限与审计

当前没有用户、角色、租户、审计。内测 MVP 前需要补：

- Demo 用户上下文。
- RBAC 最小模型。
- 审计日志。
- LLM 调用日志。

### 3.6 产品体验

当前页面能跑，但还缺真实工作流细节：

- 新建候选人/公司/证据入口。
- 任务状态实时刷新或轮询。
- LLM loading/error 状态。
- 证据草稿编辑确认。
- 导入结果报告。

## 4. 功能优先级

### P0 必须补

- 后端 LLMGateway。
- 后端证据手动录入 API。
- 证据确认后刷新评分。
- 修复评分服务乱码。
- LLM JSON 输出校验。
- 前端证据新增/确认/编辑入口。
- 阶段文档更新。

### P1 紧接着补

- CSV 导入。
- BrowserTask 真实页面读取。
- LLMRun 审计表。
- 候选人/公司搜索分页。
- 坏例闭环增强。

### P2 后续补

- 用户/权限/租户。
- PostgreSQL + Alembic。
- Worker 队列。
- 组织关系图。
- 管理者视图。

## 5. 下一阶段验收标准

- 不是只看种子数据，必须能新增一条真实候选人。
- 必须能新增或确认一条真实证据。
- 必须能基于该证据刷新评分。
- 必须能调用真实 LLM 生成摘要和触达话术。
- LLM 输出必须引用 evidence_id。
- 前端全程只调 API，不直接做 AI 或数据库逻辑。
